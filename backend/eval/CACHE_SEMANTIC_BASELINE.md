# 缓存语义匹配阈值基线

`/api/qa` 缓存第二阶段的**阈值标定记录**，与 `RETRIEVAL_BASELINE.md` 配套。
所有数字均由 `run_cache_threshold_eval.py` 在 `cache_pairs.json` 上实测得出，
不是估计值。

## 一、结论

| 项 | 值 |
|---|---|
| 生产阈值 | **0.86**（`QA_CACHE_SEMANTIC_THRESHOLD`） |
| 生效后端 | dashscope `text-embedding-v4`（1024 维） |
| 零误配前提下改写命中 | **6/10** |
| 改造前（字面归一化）改写命中 | 1/10 |
| 收益 | 改写问法的复用率 **1/10 → 6/10** |
| 误配（复用错答案） | **0/12** |

关键数字：**上界 0.797**（异义对最高相似度）、**下界 0.498**（改写对最低相似度）。

## 二、数据与方法

### 数据集（22 对，`cache_pairs.json`）

| 组 | 条数 | 含义 | 阈值方向 |
|---|---|---|---|
| paraphrase | 10 | 同一意图的不同问法（改写） | 阈值须**够低**才命中 |
| distinct | 12 | 看起来相近但答案不同 | 阈值须**够高**才拦住 |

`distinct` 里刻意放了 5 组**硬负样本**（共享课程名/活动名，只差"问时间还是问地点/方式"），
它们是本功能最主要的风险来源，也是判断余弦判据是否可用的关键样本。

### 方法：与混合权重调参完全一致

混合权重是"扫描权重看 MRR"，这里是"扫描阈值看两类代价"，两者都靠**标注数据夹出区间**
（`run_retrieval_eval.py --sweep/--calibrate` 的同款思路）：

```
下界 = paraphrase 对相似度的最小值  → 阈值必须 ≤ 它，才不漏改写
上界 = distinct  对相似度的最大值  → 阈值必须 >  它，才不误配
下界 > 上界  ⇒  存在干净分离点，阈值落在区间内
下界 ≤ 上界  ⇒  该判据无法完全分离，如实报告而不是硬挑一个"好看"的值
```

### 选取规则：零误配 → 命中最多 → 平台区取最高

两类错误代价**不对称**：漏命中只是多花一次 LLM；误配是用户拿到**另一个问题的答案**
且无从察觉，还会被缓存在 TTL 内放大（所有相近问法都拿到这个错答案）。
因此先把误配压到 0，再取命中最多的一档；命中数相同的一段区间（平台区）里取**最高**值 ——
观测收益相同，但距最难的负样本最远。

### local_hash（离线兜底后端，256 维）

| 项 | 值 |
|---|---|
| 下界 / 上界 | 0.136 / 0.667 |
| 任何阈值的改写命中 | **1/10**（与字面归一化持平） |
| 结论 | **零增量价值**，建议阈值配 0 关闭 |

同一批样本在 local_hash 上的相似度整体低一个量级：它是**字符哈希**而非语义模型，
"作业什么时候截止"与"作业截止时间是什么"的字符 bigram 重叠很少，
而"操作系统作业什么时候截止"与"线性代数作业什么时候截止"几乎只差课程名、
重叠极高（0.667）—— 于是两类区间完全交叉，任何阈值都会误配或漏放。

### 两后端对照

| 后端 | 维度 | 下界 | 上界 | 推荐阈值 | 改写命中 | 字面命中 |
|---|---|---|---|---|---|---|
| local_hash | 256 | 0.136 | 0.667 | —（无价值） | 1/10 | 1/10 |
| dashscope | 1024 | 0.498 | 0.797 | **0.86** | **6/10** | 1/10 |

> 阈值**不可跨后端通用**。把 dashscope 标出的 0.86 配给 local_hash 不会报错、
> 只是静默地什么都不命中。切换 `EMBEDDING_PROVIDER` 后必须重跑标定。
> 服务启动时会检测这种组合并打警告（见 `main.py` 的 lifespan）。

## 四、残余风险与已知边界

**必须如实说明**：0.498 ≤ 0.797，两类样本**区间重叠**，余弦单判据无法完全分离。
0.86 是在"零误配"约束下能取到的最高收益点，不是完美分离点。

1. **会漏掉的改写**（4 条，相似度 0.498~0.763）。其中「OS homework deadline ‖ 作业的截止时间」
   是中英混写，跨语言相似度天然偏低 —— 这条无论阈值取多少都救不回来。
   漏掉的代价是**多花一次 LLM**，可接受。
2. **距最难负样本的余量只有 0.063**（0.797 → 0.86）。数据集仅 22 对，
   样本外的负样本若相似度落在 0.86 以上，仍会误配。这是小规模标定的固有局限。
3. **未覆盖的问法类型**：否定问句（"报名截止了还能补报吗" 已测，0.752）、
   多跳指代（"这个"、"那个"）、超短问句（"什么时候"）。
   这些方向若出现误配，应**先补样本重跑标定**，而不是直接调阈值。
4. **对照组 0.925 而非 1.000**：仅空白差异的两句在 dashscope 上相似度 0.925。
   原因是嵌入的是**原始 query**（含首尾空格）而不是归一化后的文本。
   这不构成功能缺口 —— 空白/大小写变体由**精确 key** 路径（零成本）捕获，
   永远走不到语义路径。保留原始文本嵌入是为了让透传给检索层的向量
   与改造前**完全一致**（否则检索结果会跟着变）。

## 五、复现命令

```bash
cd campus-assistant/backend

# 两个后端都标定（需 ALIYUN_API_KEY 才能跑到真正的 dashscope）
python -m eval.run_cache_threshold_eval

# 只看某个后端；--top 控制逐对明细条数
python -m eval.run_cache_threshold_eval --embedding dashscope --top 30
python -m eval.run_cache_threshold_eval --embedding local_hash

# 改了数据集或换了 embedding 后端后：重跑并把结论写回本文件与 config.py 注释
```

## 六、后续方向

- **扩大标注集**（目标 60~80 对），重点补硬负样本，把上界压下来再看能否拉开分离区间。
- **双判据**：余弦 + 「问句意图」判定（时间/地点/方式/条件四分类），
  异义对恰好都是"同主题不同维度"，用意图标签能直接拦掉 ——
  但那是新的一次改造，且要单独标定，不在本次范围。
- **跨语言**（中英混写）需要多语言 embedding 模型，当前 `text-embedding-v4` 上限约 0.50。
