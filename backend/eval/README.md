# 抽取质量评测集

用于给「抽取准确率」提供可复现的数字，直接支撑简历里的量化描述。

## 快速开始

```bash
cd campus-assistant/backend
python -m eval.run_eval              # 跑全部样本
python -m eval.run_eval --tag 改期    # 只跑某一类难点
python -m eval.run_eval --verbose    # 逐条明细
```

## 一、样本从哪来（按优先级）

### 1. 你自己的真实校园通知 —— 首选，约 60%

最有说服力，面试时能说「来自本校真实场景」。去这些地方翻历史消息：

| 来源 | 典型内容 | 对应类别 |
|---|---|---|
| 学院/教务处官网「通知公告」栏 | 调课、停课、考试安排、选课、学分 | `course_notice` |
| 课程群 / 班群历史消息 | 作业、实验报告、ddl、提交格式 | `homework` |
| 后勤 / 宿舍群 | 报修、停水停电、空调维修 | `repair` |
| 社团公众号、学院公众号 | 讲座、招新、宣讲会、比赛、晚会 | `activity_poster` |
| 辅导员 / 年级群 | 体测、医保、奖学金、材料收集 | 多为 `other`，正好当噪声样本 |

**操作建议**：直接从聊天记录里复制原文，别自己改写——真实文本的口语化、错别字、emoji 才是压力测试的价值所在。

### 2. 公开高校官网 —— 补齐长尾，约 25%

自己学校样本不够时，搜 `<任意高校> 通知公告 调课 / 讲座 / 报修`，内容是公开可访问的。注意换掉校名、楼名，避免写成"某大学专属"。

### 3. 自己构造 + 改写 —— 约 15%

主要用于两类专项：

- **去重评测**：拿一条已有样本做同义改写（"9月10日截止" → "截止日期为九月十号"）→ 正样本对；改一个关键字段（时间 9/10 → 9/12）→ 负样本对。
- **极端难例**：跨年、改期、一文本多通知、无时间、纯噪声。真实语料里这些往往凑不齐数量。

### 4. 不推荐的来源

通用中文 NLP 数据集（DuEE、CMeEE 等）——领域是新闻/医疗，与校园通知分布差异太大，强行用会拉低数字且不可解释。

## 二、数量与难度分布

目标 **40~50 条文本 + 8~10 张图片/PDF**，建议分布：

| 类别 | 条数 | 必含难点 |
|---|---|---|
| `homework` | 10 | 绝对时间、相对日期、多时间择一、仅日期无时刻 |
| `course_notice` | 10 | 改期（原定→改为）、星期、考场/教室表述 |
| `activity_poster` | 12 | 双时间（活动时间 + 报名截止）、跨年、招新 |
| `repair` | 6 | 宿舍号、故障描述、上门时间 |
| `other`（噪声） | 6 | 无时间、含地点/设备词但非通知 |

**每条样本至少命中一个 tag**，建议覆盖这些 tag：

`绝对时间` `相对日期` `星期` `改期` `跨年` `多时间` `双时间` `无时间` `噪声` `口语化` `图片`

## 三、标注规范（关键，否则数字没意义）

### 1. 每条必须固定 `base_time`

`"base_time": "2026-08-24T10:00:00"`。否则「明天」「本周五」没有唯一正确答案，今天跑和下周跑结果不一样。

> 注意：REST API 不暴露 `base_time` 参数，所以评测脚本直接调 `run_pipeline(..., base_time=...)`，不走 HTTP。

### 2. 期望值只标「能从原文确切推出」的字段

拿不准就标 `null`。**标了但你其实是从上下文推测的，会人为拉低准确率。**

### 3. 时间字段语义

- `deadline`：截止时间。只写了日期没写时刻的，**期望值按 23:59 填**（这是系统既定规则）
- `event_time`：事件发生时间。改期场景只标**改后**的时间，原定时间不标
- 跨年：写「1月5日」而基准是 8 月 → 期望值填**下一年**（2027-01-05）
- 类别是 `homework` 或 `repair` 时，时间点通常落进 `deadline` 而不是 `event_time`（`pick_times` 的既定行为）

### 4. 类别取值是字符串，不是直觉

`Category.ACTIVITY` 的实际取值是 **`activity_poster`**，不是 `"activity"`。五个合法值：

```
course_notice | activity_poster | homework | repair | other
```

### 5. 文本字段用包含匹配判定

`course` / `location` / `issuer` 判定时会做归一化（去标点空格、全角转半角）后双向包含匹配，所以「第三教学楼A305」写成「三教A305」可能算错——**照抄原文写法**。

### 6. 图片样本

放 `eval/assets/`，在 case 里写相对路径：

```json
{"id":"img_01","input_type":"image","file":"assets/poster_lecture.jpg","base_time":"2026-08-24T10:00:00","expect":{...},"tags":["图片","讲座"]}
```

## 四、隐私与合规（别忽视）

- **脱敏后再入库**：手机号改成 `13800001234` 这类，姓名改成「张三」，学号/身份证一律删除
- 图片样本裁掉二维码，P掉人脸
- 这些样本要进 GitHub 公开仓库，群里聊天记录尤其注意——**只保留通知正文，删掉发言人和闲聊**
- 在仓库里注明样本来源为「公开通知 + 已脱敏」

全部为代码缺陷，均已逐条复核确认（非标注错误）。这就是「改进前 → 改进后」的素材。

| # | 根因 | 影响项数 | 典型样本 | 涉及位置 |
|---|---|---|---|---|
| 1 | **地点 / 发布方正则贪婪或漏词** | 12 | 「考场：A203」抽不到；噪声文本抽出「00在图书馆」「请同学们注意教室」；「图书馆」被当发布方 | `rule_extract.py` `RE_LOC_LABEL`（不认「考场」「在X」）<br>`RE_LOC_GUESS`（前导字符集含数字字母）<br>`RE_ISSUER_GUESS`（`图书馆` 在列表内） |
| 2 | **时间语义解析** | 12 | 「9月30日前」→ 判成 event 且补 09:00（应为 deadline 23:59）；<br>「今晚7点」**完全解析不出**；<br>「10月15日7:30」→ 默认成 19:30；<br>改期句取了**旧**日期 | `datetime_utils.py`：`extract_datetimes`（缺「今晚」「X日前」）<br>`pick_times`（双时间择一、改期取旧值） |
| 3 | **课程名抽取** | 4 | 「操作系统第2次作业」抽不到（无《》且无前缀）；<br>《大模型时代的软件工程》《流浪地球3》被误当课程 | `rule_extract.py` `RE_COURSE_GUESS`（要求 2-14 字前缀）<br>`RE_COURSE_BOOK`（《》一律当课程） |
| 4 | **分类误判** | 3 | 「关灯关空调」「关闭空调」误判 repair；<br>含课程名但无课程类关键词 → other | `rule_extract.py` `CATEGORY_KEYWORDS` 无否定上下文 |
