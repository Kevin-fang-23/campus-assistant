# 云端部署依赖集（Render / Railway / Fly.io 等免费层）
#
# 与 requirements.txt 的差异：**排除 paddleocr / paddlepaddle**
#   - paddlepaddle 单个包体 500MB+，还会连带拉进 opencv 等一系列重依赖；
#   - 免费实例通常只有 512MB 内存 + 构建时限，装它大概率超时或启动时 OOM 重启。
#
# 为什么排除后图片识别仍可演示：
#   保留 rapidocr-onnxruntime（几十 MB 量级，基于 onnxruntime）。
#   部署时把 OCR_PROVIDER 设为 `rapid`，直接命中它，不去探测未安装的 paddle
#   （auto 模式也能自动降级到 rapid，只是多打一条不可用日志、启动略慢）。
#
# 若连 rapidocr 也想省（追求最快构建）：删掉它并把 OCR_PROVIDER 设为 `stub`。
#   代价是图片文字识别返回空（providers/ocr.py 的 StubOCR 会明确给出 warning），
#   文本与 PDF 链路不受影响。
#
# 保留 faiss / langgraph：它们是生产路径下真正生效的后端（向量索引、流水线编排），
#   虽有 numpy / 顺序执行兜底，但只跑兜底路径会掩盖生产路径缺陷；且安装成本低。
# 保留 psycopg：体积小，便于演示后临时切 PostgreSQL 做数据持久化。
# 不含 pytest / ruff：测试与静态检查由 CI 用 requirements-ci.txt 负责，不进运行时镜像。
#
# ⚠️ 维护约定：requirements.txt 新增**核心**依赖时，这里同步加一行；
#    仅新增可选重引擎（paddle 等）时不必。
